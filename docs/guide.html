Install

You need Linux, rootless Podman 4 or newer, a systemd user session, and Go 1.27.3 or newer to build the binary. Anastasis has no other dependencies.

GOBIN=~/.local/bin go install github.com/rationislabs/anastasis/cmd/anastasis@latest
systemctl --user enable --now podman.socket

Run Anastasis as a systemd user service, so it starts with your session and restarts if it stops. Save this unit as ~/.config/systemd/user/anastasis.service (it is contrib/anastasis.service in the repository):

[Unit]
Description=anastasis container orchestrator
Requires=podman.socket
After=podman.socket

[Service]
ExecStart=%h/.local/bin/anastasis serve
Restart=always
RestartSec=1
# A user unit: it runs as you, so User= does not apply. No ProtectHome or
# ProtectSystem: anastasis reads compose files and creates bind-mount
# sources wherever a project keeps them.
NoNewPrivileges=yes
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6
LockPersonality=yes
RestrictNamespaces=yes
MemoryDenyWriteExecute=yes
SystemCallArchitectures=native

[Install]
WantedBy=default.target

systemctl --user enable --now anastasis
sudo loginctl enable-linger "$USER"   # keep running after logout; healthchecks need it too

If Anastasis stops, your containers keep running. When it starts again it adopts them instead of starting new ones.

A first project

A project is a directory with a compose.json. It follows the shape of the Compose specification, plus an x-anastasis block for what Compose has no words for:

{
  "name": "weather",
  "services": {
    "web": {
      "image": "ghcr.io/rationislabs/weather-live-dashboard:1.4.0",
      "healthcheck": {
        "test": ["CMD", "wget", "-qO-", "http://localhost:8080/health"],
        "interval": "5s"
      },
      "deploy": {
        "replicas": 3,
        "update_config": { "parallelism": 1, "delay": "5s" }
      },
      "x-anastasis": {
        "expose": "8000:8080",
        "sticky": true
      }
    }
  }
}
  • expose puts the load balancer on host port 8000, forwarding to container port 8080 of every ready replica.
  • sticky keeps each browser on one replica. Apps that keep sessions in memory need this; if that replica dies, the session is lost.
  • Use fully qualified image names (docker.io/library/nginx, not nginx): Podman may refuse to guess the registry.
cd weather
anastasis up
anastasis status

YAML works too: an existing compose.yaml loads as long as it uses the supported keys. Anything Anastasis cannot run is an error, never silently ignored.

How up converges

anastasis up reads compose.json in the current directory (else compose.yaml, else compose.yml; -f picks another file) and hands it to the running service. Then it waits, for up to 5 minutes, until every service has its replicas ready, and prints the status. It exits with an error if a rollout pauses or rolls back. up -d returns at once and prints the project name.

  • Project name: COMPOSE_PROJECT_NAME if set, else the top-level name, else the directory name, lowercased.
  • One name, one directory. A project registered from one directory cannot be brought up from another. Give two projects different name keys, or run anastasis down before moving one. Another file in the same directory is the same project, so compose.yaml can become compose.json with a plain up.
  • Variables: ${VAR}, ${VAR:-default} and the other Compose forms take their values from your environment and from a .env file next to the project file; the environment wins.
  • Running up again with a changed file updates only the services whose config changed.

Status and scaling

$ anastasis status
PROJECT  SERVICE  READY  OUTDATED  PORT  AUTO  STATE
weather  web      3/3    0         8000  -     ok
  • READY is ready replicas over the replicas wanted; OUTDATED counts replicas still on an old config during a rollout.
  • STATE is ok, starting, rolling out, crash backoff until …, paused: … or error: ….
  • Warnings follow the table, for example when healthchecks cannot run.
anastasis scale weather web=5       # lasts until the next up
anastasis down weather              # remove containers and network
anastasis down weather --volumes    # and the project's named volumes

Only stateless services scale. A service that keeps state in a local volume (SQLite, files) must stay at one replica.

Self-healing

  • Exited and unhealthy replicas are replaced.
  • A replica that dies within 30 seconds of starting puts the service in crash backoff: 1 second, doubling up to 5 minutes. Replicas that died while Anastasis was not running, such as during a reboot, are replaced without backoff.
  • A replica whose healthcheck gives no result for interval + timeout stops getting traffic, and is replaced after retries such periods. Podman 4.9 never times out a hung check by itself.
  • Replicas without a healthcheck count as ready as soon as they start.

Rolling updates and rollback

A rollout starts when a service's config changes and you run up. Anastasis defaults to order: start-first, unlike Compose's stop-first: a new replica starts and becomes ready before an old one stops, so even a single-replica service updates without downtime.

"deploy": {
  "update_config": {
    "parallelism": 1,
    "delay": "5s",
    "monitor": "30s",
    "failure_action": "rollback"
  }
}

If new replicas fail within monitor (default 30 seconds), failure_action decides:

  • pause (default): the rollout stops, and the old replicas that are left keep serving. Fix the file and run up again.
  • rollback: the old config comes back.
  • continue: the rollout carries on.

anastasis rollout restart weather web rolls every replica the same way and pulls the image again, for a moving tag such as latest.

ports: still works for single-replica services, which then update with stop-first and a short outage. Use x-anastasis.expose to scale and to update without downtime.

Autoscaling

"deploy": {
  "replicas": 2,
  "resources": { "limits": { "cpus": "0.5" } }
},
"x-anastasis": {
  "expose": "8000:8080",
  "autoscale": { "min": 1, "max": 6, "inflight": 10, "cpu": 70 }
}

replicas is the starting count, and the floor when min is left out. inflight is the target number of concurrent requests per replica; cpu the target percent of the CPU limit per replica.

  • Anastasis works out a replica count from each signal (ready replicas × observed ÷ target, rounded up) and uses the higher one, within min and max.
  • Scaling up starts within about 15 seconds, plus the time new replicas take to become ready. Scaling down waits until the load has been lower for 5 minutes, then removes one replica per minute.
  • Missing data never scales down.
  • cpu needs deploy.resources.limits.cpus, and on rootless Podman cgroup v2. On cgroup v1 the CPU signal is unavailable and anastasis status says so.
  • inflight needs x-anastasis.expose: only the load balancer counts requests. A WebSocket or server-sent-events connection counts for as long as it stays open, so scale live dashboards on cpu.
  • anastasis scale refuses autoscaled services: change min or max in the file and run up.
  • The AUTO column shows each decision, for example 2→4 (inflight 14.0/10, cpu 55/70).

Volumes and data

  • Keep state in named volumes or bind mounts. Anonymous volumes (an image's VOLUME, such as redis /data, or a volume entry without a source) belong to one replica and are deleted with it. Every replacement, rollout or scale-down starts them empty. Compose keeps them across a recreate; Anastasis does not.
  • down --volumes removes the project's named volumes, never external ones.
  • A volume belongs to one project: up refuses a project that names another project's volume. To share one, mark it "external": true in both projects.
  • A project file is trusted like a script. Bind mounts of any host path and cap_add are passed to Podman as written. Rootless Podman limits them to what your user can do, but a bind mount of your home directory can still read your files. privileged, devices and pid are refused.

Upgrading Anastasis

GOBIN=~/.local/bin go install github.com/rationislabs/anastasis/cmd/anastasis@latest
systemctl --user restart anastasis

Containers keep running while Anastasis restarts, and the new binary adopts them.

Troubleshooting

Replicas stay starting and never get traffic
Healthchecks on rootless Podman need a systemd user session. Run sudo loginctl enable-linger "$USER". anastasis status warns about this.
The load balancer cannot bind a port below 1024
Allow unprivileged ports with sysctl net.ipv4.ip_unprivileged_port_start=80 (or lower). Anastasis does not change it for you.
Podman refuses the image name
Use the fully qualified name, with the registry: docker.io/library/nginx.
up says the project belongs to another directory
See one name, one directory.
A key is “not supported”
Anastasis refuses what it cannot run instead of ignoring it. The reference lists each refused key and what to do instead.
