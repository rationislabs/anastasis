Container orchestration on rootless Podman

Anastasis keeps your services running at the size you asked for. It replaces replicas that die, balances traffic across them, rolls out updates without downtime and scales on load. One binary, one JSON project file, no root daemon, no cluster.

The name is Greek: ἀνάστασις, resurrection. What dies comes back.

What it fixes

Replicas behind one port
Run several copies of a service. A built-in HTTP load balancer follows every replica as it comes and goes. 
"deploy": { "replicas": 3 },
"x-anastasis": { "expose": "8000:8080" }
Self-healing
Exited or unhealthy replicas are replaced. A service that keeps crashing backs off, from 1 second doubling up to 5 minutes. 
"healthcheck": { "test": ["CMD", "wget", "-qO-", "http://localhost:8080/health"],
                 "interval": "5s" }
Rolling updates without downtime
Change the file and run up. New replicas start before old ones stop; if they fail, the rollout pauses or rolls back. 
"image": "ghcr.io/rationislabs/weather-live-dashboard:1.5.0"
$ anastasis up
Autoscaling
Scale on concurrent requests, CPU, or both. Scaling up starts within about 15 seconds; scaling down waits for 5 quiet minutes. 
"autoscale": { "min": 1, "max": 6, "inflight": 10, "cpu": 70 }

Run it

A project is a Compose-shaped JSON file. This one runs three replicas of a web app behind port 8000:

{
  "name": "weather",
  "services": {
    "web": {
      "image": "ghcr.io/rationislabs/weather-live-dashboard:1.4.0",
      "healthcheck": {
        "test": ["CMD", "wget", "-qO-", "http://localhost:8080/health"],
        "interval": "5s"
      },
      "deploy": { "replicas": 3 },
      "x-anastasis": { "expose": "8000:8080", "sticky": true }
    }
  }
}

Save it as compose.json, then:

anastasis up                 # waits until every replica is ready
anastasis status
curl http://localhost:8000/

The guide covers installing Anastasis and Podman first. Existing compose.yaml files load too, as long as they use the supported keys.

What it is not

  • Not Kubernetes. No cluster, no control plane, no API objects. One machine, one process under your user.
  • Not multi-host. Anastasis runs the services of one machine.
  • Not for every engine. It runs on rootless Podman 4 or newer, over Podman's API socket.
  • Not a general proxy. The load balancer speaks HTTP, round-robin over ready replicas.
  • Not for scaling state. Services that keep data in a local volume stay at one replica.
